## 1. 用户需求基线

### 1.1 平台与交付方式

- 目标系统：Debian 11、Debian 12、Ubuntu 20.04、Ubuntu 22.04。
- 目标架构：AMD64、ARM64。
- Shell-first：所有检测、修复、安装、部署、升级、回滚、诊断、卸载均由仓库的交互式 `install.sh` 统一编排。
- Go 用于长期运行的高并发探测与网关服务；Shell 负责系统识别、能力检测、依赖处理、部署和生命周期管理。
- 菜单、注释、文档和操作提示优先中文。
- 系统修复必须展示变更计划、备份、验证和回滚；不得静默覆盖默认路由、清空防火墙、开启转发、修改 SSH 策略或更换内核。

### 1.2 业务目标

- 接入数百个独立公网 IP/端口/认证信息的 SOCKS5（SK5）、Shadowsocks（SS）、L2TP 节点。
- 每个节点、每个目标 IP 独立计数；默认每节点对每个目标 IP 最多 5 个并发 TCP 流或 UDP 会话。
- 不同目标 IP 的计数相互独立。
- 加权最少连接数调度，避免按节点顺序先填满前面的节点。
- 连接名额必须原子预留；TCP 连接关闭释放名额；UDP 按五元组和空闲超时管理会话。
- 探测流量必须强制走被测节点，防止串路。
- 节点故障隔离、恢复验证、停止新分配、旧连接排空。
- 节点多数每日更换；历史探测和运行数据按 24 小时策略清理，但不得删除仍在使用的会话状态。
- 独立腾讯云 Debian Probe Server 提供 HTTP/TCP/UDP 探测端点；探测中心故障不得误判所有代理节点故障。
- 主网关基准环境：Debian 12、AMD64、4 vCPU、约 5.8 GiB 内存、根分区约 9.8 GB（可用约 8.1 GB）；磁盘不扩容，必须实施数据库、WAL、日志和临时文件容量控制。

## 3. 已发现问题与整改

### F-01 发布脚本凭据扫描顺序不安全
- 原因：先扫描已跟踪文件，再执行 `git add`，新建文件可能漏扫。
- 整改：先 `git add -A`，再扫描工作区和 Git 历史；要求安装 Gitleaks，缺失时失败关闭；检查远端、分支、暂存区格式。
- 追加保护：检测浅克隆；浅克隆先执行 unshallow 和获取标签，失败则拒绝发布。
- 当前状态：代码已修复；Windows PowerShell 实际执行测试尚未在本轮运行，第三方应验证 Windows PowerShell 5.1 与 PowerShell 7。

### F-02 发行版文件 source 导致 root 代码执行
- 原因：原逻辑允许通过环境变量指定文件并使用 `source`，文件内容会作为 Shell 代码执行。
- 整改：固定读取 `/etc/os-release`，仅提取所需键值，不 source 外部文件。
- 当前状态：已增加安全回归测试；CI 通过。

### F-03 中文函数名与 ShellCheck 不兼容
- 整改：Shell 函数名统一 ASCII；用户可见菜单、注释、文档继续中文优先。
- 当前状态：ShellCheck CI 通过。

### F-04 Gitleaks Action 默认只扫描最近提交
- 原因：官方 Action 在 push 场景日志使用 `--log-opts=-1`，不能据此宣称完整历史扫描。
- 整改：改用固定版本 Gitleaks CLI 容器，工作区扫描与 `git --log-opts="--all"` 历史扫描分开执行。
- 当前状态：GitHub Actions 日志显示工作区扫描无泄露，历史扫描 27 个提交、约 41.68 KB，无泄露。

### F-05 诊断报告包含网络敏感信息
- 整改：诊断目录权限 0700、报告文件权限 0600，并设置 umask 077。
- 当前状态：代码检查已完成；真实发行版文件系统权限验收待第三方执行。

### F-06 更新/安装/卸载功能尚未实现
- 当前状态：相关入口是明确的安全占位，不会假装完成安装或删除；Gateway Core / Probe Client 尚未包含在仓库。
- 影响：当前仓库不能作为生产网关安装包使用。
