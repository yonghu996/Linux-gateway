# 架构设计基线

## 总体原则

Shell 是统一安装、配置和运维入口；Go 是常驻服务的实现语言。安装框架与数据平面分离，Probe Client 与 Gateway Core 分离升级、独立 systemd 管理。

## 控制平面

Go Gateway Core 负责节点库存、健康状态、连接预留、按 `(节点ID, 目标IP)` 维度统计连接数、加权最少连接数调度和管理 API。

## 数据平面

- SOCKS5：独立适配器，明确认证、CONNECT 与 UDP ASSOCIATE 能力。
- Shadowsocks：采用维护中的兼容实现，不在主程序中重新实现密码学协议。
- L2TP：通过 Linux PPP 接口和策略路由使用隧道；必须检测 `/dev/ppp`、PPP 与 L2TP 内核模块。
- TCP：按连接固定出口，关闭后释放名额。
- UDP：以五元组和空闲超时定义会话，不能把 UDP 数据报误当成可靠 TCP 连接。

## 连接上限

默认每个节点对每个目标 IP 最多 5 个并发 TCP 流或 UDP 会话。名额必须原子预留，避免并发竞态。不同目标 IP 的计数相互独立。节点权重只影响同负载下的分配比例，不能突破连接上限。

## 探测

Probe Client 通过指定代理适配器访问腾讯云 Probe Server。探测路径必须与被测节点绑定，不能因为系统默认路由或其他隧道改变而误测。探测中心故障与代理节点故障必须区分。
